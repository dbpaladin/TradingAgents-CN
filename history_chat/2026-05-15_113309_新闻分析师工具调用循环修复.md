# 新闻分析师工具调用循环修复

## 会话时间
- 日期：2026-05-15
- 触发问题：002837 个股分析报告在新闻分析步骤上报错

## 问题描述
用户报告 002837 个股分析报告在新闻事件分析步骤上报错，错误信息：
> 新闻分析流程达到工具调用上限或未生成有效正文，已自动降级为占位报告。

## 根因分析

### 症状
日志显示新闻分析师被调用3次，每次调用LLM都返回了1个工具调用（`tool_calls`），但没有生成最终的分析报告：
```
08:54:52 - tool_call_count: 0/3 - LLM返回1个工具调用
08:54:55 - tool_call_count: 1/3 - LLM返回1个工具调用  
08:54:57 - tool_call_count: 2/3 - LLM返回1个工具调用
08:55:00 - 触发"新闻工具调用达到上限但报告仍为空，强制结束"
```

### 根因
在 `tradingagents/agents/analysts/news_analyst.py` 中：
1. 当LLM返回工具调用时，原代码直接返回包含tool_calls的原始AIMessage
2. 工作流循环回到分析师节点，计数器增加
3. 但LLM持续返回工具调用而从未生成最终报告
4. 计数器达到上限（3次）后，`news_report` 仍为空，触发降级报告

## 修复方案

### 修改文件
- `tradingagents/agents/analysts/news_analyst.py`

### 修改内容

#### 1. 新增补救机制（LLM未调用工具时）
当LLM未调用任何工具时，增加了新的补救逻辑：
- 如果已有工具调用历史且返回有效正文，直接接受为最终报告
- 否则强制调用统一新闻工具获取数据，然后基于数据生成分析报告

#### 2. 修改工具调用处理方式
当LLM返回工具调用时，不再返回原始AIMessage导致循环，而是：
- 直接调用新闻工具获取数据
- 基于工具返回的新闻数据生成分析报告
- 返回包含有效报告的结果

### 关键代码变更
```python
# 修改前：直接返回原始消息导致无限循环
else:
    logger.info(f"[新闻分析师] 🔧 检测到工具调用，保留原始AIMessage交回工作流执行工具")
    return {
        "messages": [result],
        "news_tool_call_count": tool_call_count + 1
    }

# 修改后：直接执行工具并生成报告
else:
    logger.info(f"[新闻分析师] 🔧 检测到工具调用，直接执行工具并生成分析报告")
    # 直接调用工具获取数据
    forced_news = unified_news_tool(stock_code=ticker, max_news=10, model_info=model_info)
    # 基于数据生成分析报告
    analysis_result = llm.invoke([{"role": "user", "content": analysis_prompt}])
```
