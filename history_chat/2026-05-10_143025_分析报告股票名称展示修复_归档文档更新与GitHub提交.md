## 用户诉求

- 用户反馈：所有分析报告都只有股票代码，没有股票名称。
- 期望直接修复报告链路，让最终报告、导出内容和下载文件名都能显示股票名称。
- 修复完成后，归档聊天记录、更新相关文档并提交 GitHub。

## 问题判断

排查后确认，问题不在于系统完全拿不到 `stock_name`，而在于报告生产链路没有统一消费这个字段：

- 数据模型、列表接口和详情页已经支持 `stock_name`
- 但多个最终产物标题仍直接用 `stock_symbol` 拼接
- 部分原始模块报告正文即使已有完整分析内容，也没有显式写出“股票名称 + 代码”
- 下载文件名同样只使用股票代码，导致用户感知为“所有报告都只有代码”

这说明根因是“最终展示与落盘链路没有统一的股票展示名规则”，而不是单一接口缺字段。

## 本轮代码修复

### 1. 服务层统一股票展示名与正文兜底

文件：`app/services/simple_analysis_service.py`

- 新增 `_get_stock_display_name()`，统一输出 `股票名称（股票代码）`
- 新增 `_ensure_report_has_stock_identity()`，在模块报告落盘前补写 `分析对象：名称（代码）`
- 分模块报告标题统一改为带股票名称的形式
- `final_trade_decision.md` 标题与正文都补上 `分析对象`
- `analysis_metadata.json` 新增 `stock_name`

这样即使上游原始内容只写了代码，保存到最终结果目录时也会被强制补齐名称信息。

### 2. 导出链路统一显示名称

文件：`web/utils/report_exporter.py`

- 汇总 Markdown 报告主标题改为 `股票名称（代码） 股票分析报告`
- 分模块导出标题统一使用股票展示名
- 导出前同样对正文执行“分析对象”兜底补齐
- 导出元数据增加 `stock_name`

### 3. 报告下载接口标题修复

文件：`app/routers/reports.py`

- 下载 Markdown 时，标题从 `股票代码 分析报告` 改为 `股票名称（代码） 分析报告`
- 下载内容开头新增 `分析对象`
- 若报告文档自身缺少 `stock_name`，继续沿用现有 `get_stock_name()` 兜底补齐

### 4. 前端下载文件名修复

文件：`frontend/src/views/Reports/ReportDetail.vue`

- 下载文件名改为优先使用 `股票名称（代码）_分析报告_日期.xxx`
- 如果名称缺失，再回退到仅股票代码
