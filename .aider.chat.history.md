```markdown
# 投资辩论状态结构文档 (Investment Debate State Structure)

## 概述
`InvestDebateState` 用于管理多头（Bull）与空头（Bear）研究员之间的动态辩论过程。该状态在 LangGraph 工作流中传递，确保对话历史、最新回复及归档记录的一致性。

## 字段说明
| 字段名 | 类型 | 描述 |
|--------|------|------|
| `bull_history` | `str` | 仅包含多头研究员的历史发言记录 |
| `bear_history` | `str` | 仅包含空头研究员的历史发言记录 |
| `history` | `str` | 完整的辩论对话历史（Bull + Bear 交替） |
| `current_response` | `str` | 当前轮次最新生成的回复内容 |
| `judge_decision` | `str` | 法官节点输出的最终决策结果 |
| `count` | `int` | 当前辩论轮次计数器 |
| `chat_archive` | `str` | 长期归档的聊天记录，附带时间戳，便于后续回溯与模型微调 |

## 归档机制 (`chat_archive`)
- 每次研究员节点执行完毕，会自动将最新回复追加至 `chat_archive`。
- 格式：`[YYYY-MM-DD HH:MM:SS] Role: Response Text\n`
- 归档记录独立于 `history`，避免在 `compact_history` 截断时丢失早期上下文。
- 可通过 `state["investment_debate_state"]["chat_archive"]` 直接提取完整时间线。

## 状态流转示例
```
START -> BullNode -> BearNode -> JudgeNode -> END
```
每个节点读取当前状态，更新对应字段后返回新状态字典，LangGraph 自动合并至全局 `AgentState`。

## 维护建议
- 若需重置辩论，初始化时将所有字符串字段设为 `""`，`count` 设为 `0`。
- 归档记录增长较快时，可在 `JudgeNode` 或外部存储层进行 JSON 序列化持久化。
```
